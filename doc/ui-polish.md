# 界面细化与配置更新反馈

日期：2026-10-29。分支：dev。

本文记录布局与更新反馈。其后的账号流量、到期信息及当前安装包见 [订阅统计记录](subscription-info.md)。

用户反馈现有版本基本可用，但配置更新没有加载动画，页面布局与 FlClash Android 的观感仍有差异。本轮完成更新反馈和界面层级调整。

## 更新操作

| 场景 | 新的反馈与行为 |
| --- | --- |
| 更新一个订阅 | 点击即进入加载态；配置行刷新图标变成原生 LoadingProgress，并显示“正在下载并验证配置” |
| 更新全部 | 工具栏、更新提示区和导航上的配置图标显示加载；提示当前配置名称、已完成数量和真实批次进度 |
| 重复点击 | 同一时刻仅执行一组更新；单个更新与批量更新不会重叠 |
| 部分失败 | 继续更新其他订阅；最终汇总成功数量，失败配置保留具体提示，可再次点击刷新重试 |
| 异常 | 网络、文件或运行配置准备异常均退出加载态，不无限转圈；提示不直接暴露异常对象中的 URL 或凭据 |
| 更新完成 | 更新最近更新时间与节点数量，显示结果提示；失败结果保留在对应配置行 |
| VPN 正在运行 | 下载文件不重置正在使用的代理列表或节点选择，当前配置更新后提示重新连接生效 |
| 同时操作配置 | 更新、导入、切换、删除、编辑保存与备份恢复之间增加互斥，避免元数据竞争覆盖 |
| 更新时启停 VPN | 仍然允许断开；文件处理完成前暂不能新建连接，避免启动过程中重复下载同一配置 |
| 手动同步代理 | 同步图标增加加载动画、防连点和失败恢复 |

批量进度表示已处理的订阅数量，包含成功和失败，不冒充网络下载百分比。单个订阅没有可用的总字节数，因此使用不确定加载动画。未增加定时器模拟进度，也没有人为延长请求等待。

新导入的订阅保存后进入配置页，继续通过同一更新流程下载，当前配置选择仍按原逻辑保留。订阅 User-Agent、格式兼容转换和 YAML 校验继续使用此前已验证的服务。

## 布局调整

参考 [FlClash v0.9.2 的移动端布局](https://github.com/chen08209/FlClash/blob/7fd417fb9a9a277c6a9339a8ac87f907df7c25f7/lib/views/dashboard/dashboard.dart)、[配置列表及更新状态](https://github.com/chen08209/FlClash/blob/7fd417fb9a9a277c6a9339a8ac87f907df7c25f7/lib/views/profiles/profiles.dart) 和 [导航结构](https://github.com/chen08209/FlClash/blob/7fd417fb9a9a277c6a9339a8ac87f907df7c25f7/lib/pages/home.dart)，沿用 ArkUI、现有紫色主题和原生交互。不是 Android 页面截图的像素复刻，也不把尚未实现的平台能力画成可用功能。

| 区域 | 调整 |
| --- | --- |
| 顶栏 | 从 88vp 双行标题改为 64vp 单行工具栏；配置页的更新和添加操作集中到右上角 |
| 底部导航 | 移除浮动大胶囊外框，改为固定整栏；只给选中图标加色调背景，文字位于图标下方 |
| 首页 | 保留一个主启停按钮，删除重复的独立 VPN 开关卡；连接状态、时间和活跃连接归到同一卡片 |
| 实时流量 | 上传与下载合并为紧凑双栏，大数字与单位分层；真实历史样本使用原生折线，空闲不绘制虚假活动柱 |
| 模式与入口 | 收紧规则/全局/直连分段控件；当前配置和代理策略并排放置，减少重复标题与滚动距离 |
| 配置 | 原来的多行大卡改为紧凑配置行；名称与节点数在左，更新和菜单在右，最近更新和当前配置标记在下方 |
| 双列节点 | 移除挤占宽度的大图标底座，名称置顶并允许两行；协议和延迟分别显示，选中状态同时保留勾选标记 |
| 间距与主题 | 主要页面使用 16vp 页边距，首页/配置/代理主体最大宽度 640vp；选中行使用较轻的语义化色调 |

控件保留原生按压效果与可访问性文字，更新时允许切换页面。底部导航放在页面内容之后，页面主体保留独立滚动区域，不用覆盖内容的浮层承载导航。字体和文字通过行数、换行、伸缩区域及最小高度适配，未锁定系统字号。

本轮应用了本机 `ui-ux-pro-max` 的加载反馈、触控目标、信息层级与明暗主题检查；通用检索产生的网页配色和技术栈建议没有替代现有 ArkUI 与产品主题。

## 实现入口

- [ProfileUpdateViewState](../entry/src/main/ets/models/ProfileUpdateViewState.ets)：更新状态、目标配置、真实完成数量和逐项结果。
- [ProfileCards](../entry/src/main/ets/components/ProfileCards.ets)：更新提示和配置行，使用 ObjectLink 接收状态。
- [AppNavigationBar](../entry/src/main/ets/components/AppNavigationBar.ets)：应用实际使用的底部导航。
- [HomeRuntimeCards](../entry/src/main/ets/components/HomeRuntimeCards.ets)：连接状态、计数和流量组件，保留高频流量与根页面分离的结构。
- [Index](../entry/src/main/ets/pages/Index.ets)：更新任务、配置写入互斥、页面布局与工具栏接入。
- [AppTheme](../entry/src/main/ets/theme/AppTheme.ets)：内容宽度、间距、圆角与选中背景；明暗资源成对维护。

- 新增 [profile-update-feedback.test.mjs](../tests/profile-update-feedback.test.mjs)，执行实际状态模型和页面更新方法。覆盖立即加载、防重复请求、真实批量进度、失败后继续、异常解除加载、重试、配置写入互斥、更新时保留实时节点，以及允许断开/阻止文件处理中启动。
- 订阅 21 项、UI 工作流、app-flow、状态推送、断开、后台生命周期和异步桥接回归通过。原 app-flow 中过时的提示文案和选中颜色断言已跟随最终实现更新，行为检查保留。
- 浅色和深色主题各检查 7 组主要文字/背景和状态颜色，对比度均达到 4.5:1。
- HarmonyOS debug 编译及签名成功，后续图标与顶端对齐修正的最终构建 15.948 秒；ARM64 HAP 内容和内核打包检查通过。原生桥接与 Go 内核没有在本轮修改。
- 当前环境无法直接操作真机，未完成实际页面截图、横竖屏和最大字号的逐页视觉验收。编译通过和颜色计算不代替手机上的布局检查。

新增 [InterfacePreview](../entry/src/main/ets/preview/InterfacePreview.ets)，可以在 DevEco 中查看生产组件的 360vp 预览样例，包含长配置名称、更新中、等待更新和失败状态；切换预览颜色模式可检查明暗主题。这些是明确标注的预览数据，不接入应用路由，不启动 VPN，也不访问网络。本轮未采集 Previewer 的实际渲染图片。

## 安装与复测

后续根据真机反馈补了两处修正：测速按钮改为 48vp 圆形纯图标，测试中保留加载动画和无障碍文字；配置页的 Scroll 明确使用 `Alignment.Top`，避免配置较少时整组内容默认居中而留下大段顶部空白。组件预览同步顶端对齐。此处属于真机反馈后的修正，前述首轮验证没有覆盖到该实际布局问题。

使用 DevEco **Run** 覆盖安装。先更新一个订阅，再更新全部，确认加载、数量及完成提示；更新期间切换页面，再返回配置页查看结果。核对首页启停、长名称配置、双列节点以及浅色/深色显示。实际断开和后台稳定性继续参考 [后台稳定性记录](background-stability.md)。
